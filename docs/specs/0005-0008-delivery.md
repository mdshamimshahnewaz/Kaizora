## Implementation decisions

- D-020: use the proposed first/last name, persisted theme and optional timezone
  slice. Username/email remain read-only in self-service; credential workflows
  remain separate. Admin profile edits must share revision protection.
- D-021: use human-assigned, case-insensitive organization-unique client codes,
  immutable after creation. Contact read/manage remain separate capabilities.
- D-022: allow no-login resources and multiple teams. Link/unlink operations
  retain history; dated team memberships use inclusive start/exclusive end.
  Only prospective changes are supported; resource retirement is not deletion.
- D-023: private projects, delivery/operations types, optional client, explicit
  initial manager membership and project role. Creation and the initial access
  grant must be atomic and bounded by the creator's delegation authority.
  Lifecycle follows the proposed draft/active/completed/archived transitions.
- D-024: extend the existing organization mutation lock to client, resource,
  team and project commands before checking current permissions. Account
  mutations serialize on the user. Use optimistic versions for edits, strict
  request fields, bounded lists and current authorization on every request.

These are implementation choices within the owner's requested draft scope,
not final UI/UX acceptance or a production policy sign-off. D-012 performance
budgets and D-013 deployment retention remain unresolved. No billing, allocation,
custom-field engine, work-item or operational queue scope is included.
