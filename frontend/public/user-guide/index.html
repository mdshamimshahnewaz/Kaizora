1. শুরু করুন — কোন কাজ কার?

এই guide Kaizora-এর বাস্তবায়িত foundation (0001–0009) ব্যবহারের জন্য। UI-তে button/field খুঁজে পেতে তাদের English নাম অপরিবর্তিত রাখা হয়েছে। উদাহরণের client, team ও project আপনি নিজে তৈরি করবেন; এগুলো আগে থেকে seed করা নেই।

প্রথমবার: operator account দিয়ে organization ও login account তৈরি করুন → owner দিয়ে member/role configure করুন → client/person/team তৈরি করুন → project ও project access দিন → সাধারণ member দিয়ে ফল যাচাই করুন।
পরিচয়কাজ
OperatorOrganization এবং প্রথম owner নির্ধারণ। Provisioning permission নিজে থেকে organization access দেয় না।
Organization ownerনিজ organization-এর সদস্য, roles ও business setup; ownership transfer।
সাধারণ memberনিজের account ও organization পরিচয়; business কাজের জন্য assigned permission দরকার।
Django staffAdmin-এ ঢুকতে পারে; business কাজের জন্য tenant permission-ও লাগবে। শুধু staff/superuser হলেই সব organization দেখা যায় না।

প্রতিটি organization আলাদা workspace। একই user দুই organization-এ থাকলেও role ও data আলাদা।

2. Login, navigation ও logout

  1. App URL খুলে username এবং password দিয়ে Sign in করুন। Email দিয়ে login নয়। Account active থাকতে হবে। Public signup/invitation/password-reset flow এখন নেই; account দরকার হলে administrator-কে বলুন।
  2. Organizations থেকে workspace খুলুন। উপরে organization-এর নাম দেখে কাজ শুরু করুন। Switch organization দিয়ে পরিবর্তন করুন।
  3. Sidebar অথবা workspace tabs থেকে Projects, Clients, People, Teams, Settings & access খুলুন। Organization না বাছলে আগে organization নির্বাচন করতে হবে।
  4. উপরের menu toggle desktop-এ sidebar ছোট করে icon-only রাখে; mobile-এ menu খুলে navigation করুন।
  5. Account menu → Sign out। Shared computer-এ কাজ শেষে sign out করুন।

একই browser ও hostname-এ Admin এবং app একই session ব্যবহার করে। একটিতে logout করলে অন্যটির session-ও শেষ হয়। দুই user পাশাপাশি test করতে একটি normal ও একটি private browser window ব্যবহার করুন।

List-এ search লিখে Search চাপুন; status filter ও Previous/Next দিয়ে বাকি records দেখুন। Empty list মানেই record মুছে গেছে নয়—filter, organization ও permission যাচাই করুন।

সূচিতে ফিরুন ↑

3. My account — profile ও preferences

  1. My account খুলুন। Profile-এ নিজের first/last name পরিবর্তন করে save করুন। Username/email self-service-এ read-only।
  2. Preferences-এ theme ও timezone নির্বাচন করে save করুন। Theme-এ light/dark/system ব্যবহার করতে পারবেন।
  3. Timezone যেমন Asia/Dhaka দিন। Personal timezone না থাকলে workspace-এর timezone ব্যবহৃত হয়; workspace ছাড়া fallback UTC হতে পারে।
  4. Reload করে saved name/preferences যাচাই করুন।

উদাহরণ: Rahim নিজের display name ঠিক করলে login username বদলাবে না। Project access ও login-link history-র timestamps personal timezone-এ দেখানো হয়। Team membership-এর business date সবসময় organization timezone মেনে চলে।

অন্য tab থেকে account পরিবর্তন হলে stale save প্রত্যাখ্যাত হতে পারে। Latest state দেখে পরিবর্তন মিলিয়ে আবার save করুন।

সূচিতে ফিরুন ↑

4. Organization setup ও membership

নতুন organization

  1. Operator হিসেবে Organizations → Create organization খুলুন। Active superuser অথবা organizations.bootstrap_organization permission প্রয়োজন।
  2. Name: Example Studio, timezone: Asia/Dhaka, owner username: একটি existing active user দিন।
  3. Create করে owner account দিয়ে organization খুলুন। Operator অন্য কাউকে owner করলে operator স্বয়ংক্রিয় member হয় না।

Existing user যোগ

  1. Owner হিসেবে workspace → Settings & access → Members খুলুন।
  2. Add member-এ exact username দিন। Account না থাকলে আগে Django Admin থেকে user তৈরি করতে হবে।
  3. Member তৈরি হলেই business permission পাওয়া যায় না; পরের অধ্যায়ের role assign করুন।
কাজফল
Suspend / End membershipOrganization access বন্ধ; membership/history মুছে যায় না।
Reactivateএকই membership ফিরে আসে। আগে revoke না করা live role আবার কার্যকর হতে পারে; roles যাচাই করুন।
Transfer ownershipActive owner একটি active member-কে ownership দেয়। Confirm করার পর আগের owner তার owner ক্ষমতা হারায়; custom grants থাকলে সেগুলো থাকে।

Status/ownership পরিবর্তনের business reason দিন। Owner management reserved; non-owner member manager owner membership নিয়ন্ত্রণ করতে পারে না। শেষ active owner-এর সুরক্ষা আছে।

5. Roles ও permissions configure করুন

  1. Owner হিসেবে Settings & access → Roles → Create role খুলুন।
  2. Role name, scope ও permissions নির্বাচন করুন। Preset বেছে শুরু করতে পারেন, কিন্তু save করতেই হবে।
  3. Organization scope হলে Role assignments → Assign role থেকে member, role ও reason দিয়ে assign করুন। Picker-এ target না দেখলে Members/ Roles-এর প্রয়োজনীয় page আগে দেখান।
  4. Project scope role organization assignment-এ দেবেন না; project create বা project-এর Grant access থেকে ব্যবহার করুন।
Preset কোনো user-কে auto-assign করে না। Member preset-এ business permission নেই। Organization administrator ব্যাপক authority দেয়—সাধারণ sample user-এর জন্য ব্যবহার করবেন না।

Settings & access প্রতি মিনিটে এবং window-তে ফিরে এলে background-এ access যাচাই করে। সফল refresh চলাকালে page loading screen-এ বদলায় না। Organization বদলালে বা access check ব্যর্থ হলে আগের private content সরানো হয়।

Permissions additive: একাধিক active role-এর ক্ষমতা একত্র হয়। Role revoke/archive করলেও অন্য role বা ownership থেকে একই ক্ষমতা থাকতে পারে। projects.read_all organization-এর সব project পড়ার ক্ষমতা; এটি manage permission নয়।

Role edit/archive বা assignment revoke করতে reason দিন। Changes পরের request-এ কার্যকর হয়। Non-owner নিজের ক্ষমতার বাইরে role তৈরি/সম্পাদনা/delegate করতে পারে না।

6. Clients ও Contacts

  1. Workspace → Clients → Create client। Client code ACME, Client name Acme Services দিয়ে create করুন।
  2. Client খুলে name edit করতে পারেন; reason দিন। Code immutable ও organization-এর মধ্যে case-insensitive unique—acme ও ACME আলাদা code নয়।
  3. Add contact: Contact name Mina Example, Email mina@example.com, Phone optional, Position Operations contact। Contact একটি business contact, login account নয়।
  4. Contact edit করে status Retired করতে পারেন; active/retired/all filter দিয়ে দেখুন।
  5. Client-এর Archive action-এ reason দিন। ফিরিয়ে আনতে Archived clients filter → client → Restore।

Client archive করলে existing project বা history মুছে/স্বয়ংক্রিয় archive হয় না। Archived client নতুন project বা নতুন contact-এর জন্য পাওয়া যাবে না; আগে restore করুন। Contact details দেখার জন্য আলাদা contacts.read, পরিবর্তনের জন্য contacts.manage প্রয়োজন। Reason-এ phone/email পুনরায় লিখবেন না।

7. People — existing member অথবা no-login resource

Existing user-এর জন্য আবার person বানাবেন না। Organization member-কে Team অথবা Project Workforce-এর searchable dropdown থেকে সরাসরি বাছুন। প্রয়োজনীয় stable resource identity automatically তৈরি বা reuse হবে; নাম/code আবার দেওয়া লাগে না।

Login নেই এমন কর্মী

  1. People → Create person। Display name দিন, যেমন External analyst। Person code optional—খালি রাখলে নিজে তৈরি হবে।
  2. এতে login account, password বা system access তৈরি হয় না। TL/PM এই resource-কে team বা project workforce-এ যোগ করতে পারে।
  3. ভবিষ্যতে login পেলে আগে organization member বানিয়ে person details → Link login থেকে searchable dropdown-এ বাছুন; নতুন person তৈরি করবেন না।

Existing member-কে People list-এ আগে রাখতে চাইলে

Add existing member → নাম/username দিয়ে search → select → Add member as resource। Existing live identity থাকলে সেটিই reuse হবে। প্রয়োজন: resources.read, resources.manage, resources.link_identity ও memberships.read। Team/Project থেকে সরাসরি select করলে এই আলাদা step লাগে না।

Person code creation-এর পরে immutable। Retire/reactivate এবং login-link end-এর পুরোনো history থাকবে। Retired identity-কে silently নতুন করে তৈরি করা হয় না; আগে reactivate করুন। আগের login link ended হলে existing person-কে explicit relink করতে হবে, যাতে identity duplicate না হয়। একই নাম দেখে দুই resource auto-merge করা হয় না।

Login link শেষ করলে account বা project access revoke হয় না। Offboarding-এর আলাদা steps অনুসরণ করুন।

8. Teams ও dated membership

  1. Teams → Create team: Team code OPS-A, Team name Operations A দিন।
  2. Team খুলে Add person → Add person to team dialog-এ Existing member অথবা Existing resource / no-login worker নির্বাচন করুন। Dropdown খুলে নাম/username search করে বাছুন; member হলে resource স্বয়ংক্রিয় তৈরি/reuse হবে। Start date হিসেবে organization-এর আজকের দিন বা ভবিষ্যৎ দিন দিন। End date ongoing হলে খালি রাখুন।
  3. Team থেকে সরাতে membership-এর Set end date দিন; reason লিখুন। এটি row delete নয়।
  4. As of date দিয়ে নির্দিষ্ট দিনের সদস্য দেখুন। All history দিয়ে future/ended intervals-সহ সব history দেখুন; Today বর্তমান দিন ফিরিয়ে দেয়।
তারিখের উদাহরণ: Start 1 November, end 10 November হলে ব্যক্তি 1–9 November সদস্য; 10 November থেকে নয়। Form-এ আপনার বর্তমান দিনের তুলনায় বৈধ তারিখ নিন। একই person একই team-এ overlapping interval হতে পারে না; আলাদা একাধিক team-এ থাকতে পারে।

Backdated correction এখন নেই; today/future changes ব্যবহার করুন। ইতিমধ্যে শেষ interval rewrite করা যায় না। Team archive করলে history থাকে এবং new assignment বন্ধ হয়। Team membership থেকে project access, staffing allocation বা billability পাওয়া যায় না।

10. Project access grant ও revoke

  1. Settings & access-এ প্রয়োজনমতো project-scoped Project reader role তৈরি করুন (projects.read)।
  2. Project details → Project access → Grant access। Active organization member, delegable project role এবং reason নির্বাচন করুন।
  3. উদাহরণ: Nadia-কে Project reader দিলে সে এই project পড়তে পারবে, edit/access management করতে পারবে না।
  4. সরাতে live grant-এর End access দিয়ে reason লিখুন। পুরোনো grant history থাকবে।

Access list পড়তে projects.access.read, grant/end করতে projects.access.manage প্রয়োজন। Grant করার সময় role-এর প্রতিটি permission নিজের authority-র মধ্যে হতে হবে। নতুন role বানালেই existing manager সেটি দিতে পারবে এমন নয়।

Member suspended/ended বা role archived হলে live grant থাকলেও কার্যকর access বন্ধ থাকে। Restore/reactivate করলে unrevoked grant আবার কার্যকর হতে পারে। অন্য role বা owner/read_all থেকে access আছে কি না দেখে revocation যাচাই করুন।

People login link, team membership এবং project access তিনটি আলাদা সম্পর্ক। Access grant staffing, replacement, time approval বা billing rate নির্ধারণ করে না।

Project Workforce — কে কাজ করবে

Project access নির্ধারণ করে কে application-এ project খুলতে পারে। Workforce নির্ধারণ করে project-এ কে কাজ করে; login নেই এমন কর্মীও এখানে থাকে। একটির সঙ্গে অন্যটি auto-assign হয় না।

  1. Owner অথবা projects.manage-সহ project manager হিসেবে project details খুলুন → Workforce → Add worker।
  2. Existing member বেছে নাম/username search করুন। অথবা Existing resource / no-login worker বেছে People-তে তৈরি resource search করুন।
  3. Reason যেমন Assigned for data review দিয়ে Add worker করুন। Member-এর resource আগে থাকলে reuse হবে; না থাকলে auto-create/link হবে। কোনো নতুন login বা access grant হবে না।
  4. কাজের assignment শেষ হলে End work assignment → reason → confirm করুন। পুরোনো row/history থাকে; একই worker পরে নতুন assignment পেতে পারে। একই project-এ duplicate live assignment নিষিদ্ধ।

Project reader roster দেখতে পারে, বদলাতে পারে না। PM-এর project-level management authority দিয়েই eligible org member/resource বাছা যায়; organization admin হওয়া লাগে না। Archived project-এ নতুন worker যোগ হয় না; restore করুন। Project access না থাকলে workforce-এ নাম থাকলেও login করে project দেখা যাবে না।

বর্তমান সীমা: এটি worker roster foundation। TL/PM-এর পক্ষে task/time entry, approval, hours, billability বা replacement tracking এখনো তৈরি হয়নি। পরের feature-এ এই stable resource ID ব্যবহার করা যাবে; এখনই কাজের hours log করার screen নেই।

Roster-এ assignment সময়ের নাম রাখা হয়; পরে person rename করলে পুরোনো assignment label বদলায় না। Resource/member removal-এ আগের worker identity মুছে যায় না।

15. Operator configuration — local environment

এই অধ্যায় installation/operator-এর জন্য; end user-এর terminal বা database access প্রয়োজন নেই। Existing working environment হলে পুনরায় setup করবেন না। Repository README-তে dependency installation আছে।

Backend .env

backend/.env.example প্রথমবার copy করে backend/.env বানান। Existing file overwrite নয়। বর্তমান Django settings DATABASE_URL পড়ে; শুধু DB_NAME/DB_USER/DB_PASSWORD/DB_HOST/DB_PORT লিখলে database configure হবে না।

DJANGO_DEBUG=True
DJANGO_SECRET_KEY=replace-with-a-local-secret
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1
DJANGO_CSRF_TRUSTED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
DATABASE_URL=postgresql://app_user:YOUR_PASSWORD@localhost:5432/timely_v4

নিজের existing database/user/password বসান। সাধারণ PostgreSQL port 5432; repository Docker Compose ব্যবহার করলে host port 55432। Actual configured port নিন—543 ধরে নেবেন না। URL password-এর special characters percent-encode করুন। Secret repository বা user guide-এ রাখবেন না।

Migration এবং দুই terminal-এ run

# Repository root থেকে, existing virtual environment ব্যবহার করে
backend/.venv/bin/python backend/manage.py migrate
# প্রথম operator না থাকলে শুধু তখন:
backend/.venv/bin/python backend/manage.py createsuperuser

# Terminal 1
backend/.venv/bin/python backend/manage.py runserver 127.0.0.1:8000

# Terminal 2
npm run dev --prefix frontend

App http://localhost:5173, Admin http://localhost:8000/admin/, এই guide http://localhost:5173/user-guide/। Vite-এর local proxy backend-এ API request পাঠায়। Settings change হলে backend restart করুন।
